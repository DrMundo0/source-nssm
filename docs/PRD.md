# PRD：NSSM 项目产品需求文档

## 1. 文档目的

本文档用于说明项目在 Windows 平台下将任意可执行程序封装为系统服务的产品定位、用户需求、功能边界和版本目标，作为后续开发、测试和交付的统一依据。

本项目是对开源 NSSM 的维护增强版本。项目目标不是简单克隆，而是在保持原有命令行兼容性的前提下，持续提升可用性、稳定性和中文化体验，并为企业级部署场景提供更成熟的服务管理能力。

## 2. 项目概述

### 2.1 项目名称
NSSM（Non-Sucking Service Manager）

### 2.2 中文定位
将任意可执行程序作为 Windows 服务运行并进行管理的工具。

### 2.3 产品价值
- 让普通应用程序能够以 Windows Service 方式长期稳定运行。
- 提供标准化服务生命周期管理：安装、启动、停止、重启、删除。
- 支持无缝接入 Windows 运行环境，减少后台进程因会话退出而中断的问题。
- 统一日志、环境变量、退出动作与重启策略，降低运维复杂度。
- 支持 GUI 与 CLI，两种管理方式兼容。

## 3. 用户画像

### 3.1 目标用户
- Windows 运维人员
- 应用部署工程师
- 后台服务开发者
- 需要在服务器上长期托管程序的团队

### 3.2 用户场景
- 将自研程序注册为系统服务，实现后台常驻。
- 让任务程序在机器重启后自动恢复并继续运行。
- 对服务进程输出日志、环境变量和重启策略进行集中管理。
- 通过图形化配置界面快速设置服务参数。

## 4. 用户需求

### 4.1 核心需求
1. 能够将任意可执行程序注册为 Windows 服务。
2. 能够管理服务的生命周期：安装、移除、启动、停止、重启、暂停、继续。
3. 能够配置服务运行参数，包括可执行文件、参数、工作目录。
4. 能够配置服务账户，支持 LocalSystem 或指定用户。
5. 能够控制服务的启动类型、依赖关系和恢复策略。
6. 能够捕获服务标准输出/错误，并支持日志轮转。
7. 能够按需要设置环境变量、优先级、亲和性和退出动作。
8. 能够在命令行与 GUI 中均可使用，降低使用门槛。

### 4.2 增强需求
1. 支持中文界面文案和日志提示。
2. 支持更现代的 Windows 行为兼容。
3. 支持 32/64 位构建产物。
4. 支持持续构建与工件归档。
5. 支持对历史兼容问题进行修复，如交互式服务失效项和稳定性问题。

## 5. 产品目标

### 5.1 业务目标
- 提供稳定、可靠的 Windows 服务托管能力。
- 让中小型团队可以在较低成本下管理后台服务。
- 在保持上游 NSSM 兼容性的基础上，提升中文用户体验和维护质量。

### 5.2 功能目标
- 服务管理完整性：覆盖 install/edit/remove/list/status 操作。
- 系统集成能力：支持依赖、账户、退出动作、恢复策略、重启控制。
- 运行监控能力：输出日志、轮转管理、标准流管理。
- 兼容性与安全性：Windows 7+、管理员权限、运行时安全约束。

### 5.3 非功能目标
- 尽量保持与原始 NSSM 命令行参数不破坏。
- 适配现代 Windows 系统行为，消除已失效功能的误导。
- 高可用性：避免句柄泄漏、临时内存问题、注册表配置错误等稳定性问题。
- 易维护性：模块清晰、接口明确，便于后续扩展。

## 6. 功能需求

### 6.1 服务安装与删除
- 支持将可执行程序安装为 Windows 服务。
- 支持删除已安装服务。
- 安装和删除操作要求管理员权限。

### 6.2 服务配置
- 支持设置程序路径、参数和工作目录。
- 支持设置服务显示名称和描述。
- 支持设置服务启动方式：自动、延迟自动、手动、禁用。

### 6.3 账号与权限
- 支持 LocalSystem、指定用户、虚拟服务账户等模式。
- 支持账号与密码配置。
- 支持服务登录权限校验和身份规范化。

### 6.4 服务依赖
- 支持配置依赖服务。
- 支持配置依赖服务组。
- 支持在启动顺序中保证依赖服务先启动。

### 6.5 进程控制
- 支持优先级配置。
- 支持 CPU 亲和性配置。
- 支持控制台可见性与开关配置。
- 支持优雅停止策略：Console / Window / Thread 清理。

### 6.6 日志与输出
- 支持 stdout/stderr 重定向到文件。
- 支持日志按时间和大小进行轮转。
- 支持在线轮转和离线轮转两种模式。

### 6.7 环境与退出动作
- 支持替换式环境变量与追加式环境变量。
- 支持退出动作定义：忽略、重启、退出。
- 支持节流和重启延迟控制。

### 6.8 事件钩子
- 支持 servic e start/stop/exit/power/rotate 阶段的 pre/post/change/resume 钩子。
- 支持执行脚本或程序。
- 支持超时控制和上下文环境变量注入。

## 7. 非功能需求

### 7.1 兼容性
- 目标操作系统：Windows 7 及以上。
- 支持 32 位/64 位 Release 构建。
- 与原始 NSSM 的核心命令行接口保持兼容。

### 7.2 稳定性
- 修复句柄泄漏、内存释放问题、边界检查问题和注册表类型问题。
- 避免不必要的交互式服务选项，以减少误导和兼容性风险。

### 7.3 安全性
- 服务安装与删除应要求管理员权限。
- 密码等敏感内容应在内存中及时清理。
- 对未知或非法参数输入应输出标准错误并记录事件日志。

### 7.4 可维护性
- 模块职责清晰，便于功能扩展。
- 配置参数纳入统一 settings_t 定义。
- 保持中文/英文文案和资源分离。

## 8. 产品范围

### 8.1 在范围内
- Windows 服务安装与管理
- 服务参数配置
- 日志与轮转
- 退出动作与重启
- GUI/CLI 操作
- 中文界面文案整理

### 8.2 不在范围内
- 非 Windows 平台支持
- 复杂分布式服务编排
- 完整的云环境部署管理平台
- 大规模统一监控系统集成

## 9. 验收标准

### 9.1 功能验收
- 能成功安装并启动一个自定义程序服务。
- 能正确编辑服务参数，并在重启后生效。
- 能在服务退出时按配置进行重启或退出。
- 能正确输出 stdout/stderr 到日志文件。
- 能按配置完成日志轮转。

### 9.2 稳定性验收
- 连续执行安装/启动/停止/删除流程，无异常崩溃。
- 无明显句柄泄漏和内存异常。
- 构建链路可在 CI 中稳定产出 Release 包。

### 9.3 体验验收
- 中文界面、提示、事件日志可理解。
- 命令行说明清晰且与官方语义一致。
- GUI 不展示失效项。

## 10. 版本规划

### v3.0.0 目标
- 明确 Windows 7+ 兼容基线。
- 移除无效交互式服务配置项。
- 错误修复和稳定性提升。
- 中文文案统一。
- 兼容 32/64 位 Release 构建。

### 后续演进方向
- 更完善的事件钩子和脚本集成。
- 更系统化的单元/回归测试。
- 更详细的端到端服务管理示例。
- 更友好的文档和 release 说明。

## 11. 结论

NSSM 项目本质上是一个 Windows 服务托管与管理工具，核心价值在于把一切“普通程序”提升为“系统服务”。从产品视角看，项目不仅要满足基础启动和停止功能，还要具备稳定性、安全性、日志与配置管理能力，以及清晰的用户体验。

随着维护增强和中文化整理的推进，项目已经从一个传统命令行工具升级为更注重工程化和可维护性的 Windows 服务管理解决方案。
